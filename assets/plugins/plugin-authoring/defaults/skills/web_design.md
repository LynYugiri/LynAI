# 前端设计

当用户要求设计或重做 Web 产物——插件功能页、独立网页、落地页、dashboard、原型、slide deck、数据可视化、UI mockup——或要求"做得好看一点、换个风格、帮我评审这个页面"时使用。本 skill 把 Agent 定位为设计工程师：先理解产品语境，再声明设计系统，先出 v0 让用户纠偏，再完整构建，最后验证。基准不是"能用"，而是"惊艳"：每个像素都有意图，每次交互都经过设计。

不适用：纯后端、CLI、非视觉逻辑、把长文转换成网页文章（那是独立文章类工作流）。

## 工作流

### Step 0：动手前先核实事实

涉及真实品牌、产品、人物时，先核实再设计，不要凭训练数据记忆臆造。

### Step 1：理解需求（按语境决定是否追问）

- 目标、受众、用途、交付物形态（功能页/落地页/dashboard/原型/slide）。
- 已有素材：品牌规范、Figma、截图、logo、文案、真实数据。
- 关键字段缺失才追问，聚焦一两个问题，不要连环盘问。

### Step 2：按优先级收集设计上下文

1. **品牌/用户提供的资产**（规范 > 截图 > 口头描述）——有就照搬，不发明。
2. **既有 UI**——扩展时匹配既有视觉词汇，不要另立风格。
3. **用户明确要求**——如指定风格锚点（"Linear 风""MUJI 感"）。
4. **风格配方速查**（见下文）——用户没想法时给出差异化方向。

### Step 2b：设计校准五刻度

把需求翻译成五个可见决策（1–10 整数），写进设计系统声明：

| 刻度 | 控制什么 | 低（1–3） | 中（4–7） | 高（8–10） |
| --- | --- | --- | --- | --- |
| 视觉变体 | 构图偏离常规的程度 | 稳定网格、对称 | 一两处不对称、节奏变化 | 强艺术指导、越界构图 |
| 动效强度 | 时间承载多少含义 | 静态、仅状态反馈 | 悬停/入场/编排 | 电影感转场、滚动叙事 |
| 信息密度 | 每屏有用信息量 | 画廊式留白 | 均衡的产品密度 | 驾驶舱式、需强分组 |
| 资产依赖 | 对真实图片/截图的依赖 | 排版与数据可撑起 | 少量关键视觉显著加分 | 无高质量资产即失败 |
| 品牌保真 | 既有身份须保留多少 | 全新/探索性身份 | 保留可识别线索 | 扩展级，须原生融合 |

预置参考（起点而非规定值）：主流 SaaS 落地页 6/5/4/6/5；创意工作室 8/7/3/8/4；开发者工具落地页 6/5/5/6/6；数据 dashboard 4/3/8/3/7；政务/机构服务 3/2/6/3/9；既有产品扩展 = 匹配现状 + 保真 10。

冲突消解：高变体+高密度 → 保持稳定导航与网格脊柱，只在一个层级做实验；高动效+高密度 → 只给转场和焦点动效；高资产依赖 → 先盘点资产再做布局，**不要用装饰性 CSS 掩盖缺失资产**；无障碍约束永远优先于美学分数。

### Step 3：写代码前先声明设计系统

用 Markdown 写出设计决策，**让用户确认后再动手**：

```markdown
设计决策：
- 设计速读：[一句话概括 + 五刻度数值]
- 风格锚点（如有）：[如 "linear 风" 或 "自定义"]
- 色彩：primary / secondary / neutral / accent（按角色命名，不搞 12 级色阶）
- 字体：标题 / 正文 / 代码（真实字体名 + 字重，不要默认 Inter 衬底）
- 间距系统：[基准单位与倍数，如 4/8/12/16/24/40/64]
- 圆角策略：[大/小/锐利]
- 阴影层级：[elevation 1–5]
- 动效风格：[缓动曲线 / 时长 / 触发]
```

风格配方速查表（下文）的存在就是为了让你不用临场发明这些值——临场发明正是"默认 Inter + #3b82f6 一锅糊"的头号来源。

**检查点 1**：声明完停下，说"我打算用这套系统，确认后我开始 v0"，然后真的等。

### Step 4：尽早出 v0

不要憋大招。用占位符 + 关键布局 + 已声明设计系统拼一个可看的 v0：

- 包含：核心结构、色彩/字体 token、关键模块占位（显式标注 `[image]` `[icon]`）、设计假设清单。
- 不包含：完整内容、组件全量、所有状态、动效。
- 目的：让用户尽早纠偏（基调对不对、布局方向对不对）。

一个带假设和占位的 v0 比耗时 3 倍的"完美 v1"更有价值——方向错了，后者整个作废。

**检查点 2**：v0 必须推给用户再继续。

### Step 5：完整构建

v0 通过后写完整组件、补状态、做动效（动效决策先加载 `plugin-authoring__motion_design`）。构建中遇到非平凡决策（交互方案、内容变体、布局级调整）再暂停确认，不要闷头推进。

### Step 6：验证

交付前做轻量自检：布局与栅格、响应式（窄屏/宽屏）、`prefers-reduced-motion`、对比度、图片资产、文案真实性与语言一致性。**只有用户明确要求"验收/QA/浏览器测试/响应式检查"时才跑可执行浏览器验收**，不要从"做好、完善、检查一下"推断出验收请求。

### Step 7：交付前自审（或应要求评审）

按下方反套模板清单自查一遍再交付。

## 反 AI 套模板清单（每条都先问 WHY）

反套模板不是审美洁癖，是保护用户品牌识别：AI 默认 = 训练数据均值 = 所有品牌平均在一起 = 没有品牌被识别。每条规则唯一的合法例外是"品牌规范自己用了它"——那一刻它从 slop 变成品牌签名。

| 模式 | 为什么是 slop | 什么时候可以 |
| --- | --- | --- |
| 紫→粉→蓝激进渐变 | 训练数据收敛出的"科技感公式"，每个 SaaS/AI 落地页都有 | 品牌自己用它，或任务在调侃这种审美 |
| 圆角卡片 + 彩色左边框 | Material/Tailwind 时代残留，dashboard 视觉噪音 | 用户明确要求或品牌规范保留 |
| emoji 当图标/装饰 | "不专业 → 贴个 emoji"的训练数据惯性 | 品牌本身用 emoji（Notion、早期 Linear） |
| SVG 手绘人像/场景 | AI 画的人脸特征错位、廉价 | 几乎永远不要——用真实图片或诚实占位 |
| CSS 剪影冒充产品图 | 每个品牌长得一样的"科技感" | 品牌工作永远不要——去取真实产品图 |
| Inter/Roboto/Arial 当展示字体 | 太常见，读起来像 demo 页而非设计过的产品 | 品牌规范指定（通常还带定制调整） |
| 伪造数据、假 logo 墙、假用户评价 | 数字对不上现实时用户会发现，损害可信度 | 永远不要——用标注"需真实数据"的占位符 |

页面级反模式：每个小节都套"小号 eyebrow + 标题 + 段落"三段式；三连以上左右交替图文之字形；无脑居中 hero + 渐变 + 两个 CTA；装饰性"信任剧场"（无意义的徽章墙）。修复思路：变化层级用引导句/图片/数字/引号/直接大标题；之字形单调处插入整宽证明点、纵向叙事、对比、画廊或专注文本段。

## 占位哲学

缺图标、缺图、缺组件时，**占位符比画得难看的假货更专业**：

- 缺图标 → 方块 + 标签（`[icon]`、`▢`）；缺头像 → 首字母圆形色块；缺图片 → 带比例信息的占位卡（如 `16:9 image`）；缺数据 → 主动向用户要，**永远不编造**；缺 logo → **停下来问用户**，品牌工作绝不用"色块里写品牌名"冒充 logo。

占位符传递的是"这里需要真实材料"；假货传递的是"我在偷工减料"。

## CSS 与实现最佳实践

- 布局优先 CSS Grid + Flexbox；设计 token 用 CSS 自定义属性集中管理。
- 色彩优先品牌色；需要衍生色时用 `oklch()` 调和，**不要凭空发明新色相**。
- 流体排版用 `clamp()`；组件级响应式用 `@container` 查询；行尾用 `text-wrap: pretty`。
- 必须覆盖 `@media (prefers-reduced-motion)` 与 `@media (prefers-color-scheme)`。
- **LynAI 功能页优先自包含**：CSS/JS 内联或同目录引用；不依赖 CDN 时不要热链外部脚本/字体，用系统字体栈（`system-ui, -apple-system, "Segoe UI", sans-serif`）或随插件打包的字体；确实需要 CDN 资源时锁定版本并说明。
- 多个组件文件共用一个 HTML 时，样式对象要命名空间化，不要用全局 `styles` 变量互相覆盖。
- 嵌入式预览里不要用 `scrollIntoView`（会干扰外层滚动），用 `scrollTop` / `window.scrollTo`。
- 大文件（>1000 行）拆小文件组合；大改版保留 v2/v3 副本；多变体优先单文件 + 参数切换面板而非多文件。

## 输出类型指南

- **插件功能页**：移动端 WebView 语境——触控目标 ≥ 44px、底部安全区（`env(safe-area-inset-*)`）、首屏即核心内容、桥接调用（`window.LynAI` / `webkit.messageHandlers`，以宿主注入为准）要有加载/失败反馈。这是"产品里的页面"，匹配 App 既有视觉词汇。
- **落地页**：一屏一个主信息；hero 决定第一印象，不要默认居中渐变三件套；真实产品截图 > 一切装饰。
- **dashboard**：先定信息层级与扫描路径再排组件；弱化边框噪音（细线 `rgba` 边框优于实线）；强调色 < 5% 像素。
- **原型**：不要封面页，视口内直接见产品；关键交互路径可点击；状态覆盖 default/hover/active/focus/disabled/loading/empty/error。
- **slide deck**：1920×1080 舞台、文本 ≥ 24px、一次一屏一个论点、点击推进。
- **数据可视化**：最大化数据墨比（data-ink ratio）、最小有效差异、不堆装饰图表。

## 风格方向与配方速查

用户没想法时给 3 个来自**不同学派**的差异化方向（含命名设计师/工作室 + 两三句"为什么适合你" + 3–4 个签名视觉特征），让用户选一个或混合两个。六大派系：

1. **信息架构派**（理性、数据驱动）：Pentagram、Tufte、Vignelli、Bloomberg Terminal、NYT 报章。
2. **编辑极简派**（留白、安静奢华）：MUJI/原研哉、Apple HIG、Dieter Rams、Aesop、Monocle。
3. **动效实验派**（电影感、叙事）：Resn、Active Theory。
4. **粗野/原始派**（反精致、直给）：Balenciaga、Are.na。
5. **温暖人文派**（手作感、亲和）：Mailchimp、Headspace、Mid-century。
6. **现代工具/构建者派**（安静的专业）：Linear、Vercel、Raycast。

常用配方速查（选中后直接用，不要全表读一遍）：

- **linear**：底色 `#08090A` 暖黑、表面 `#16171C`/`#1E1F25`、发丝边框 `rgba(255,255,255,0.06)`、唯一强调紫 `#5E6AD2`（<5% 像素）；Inter Tight 600 标题（字距 -0.02em）+ 等宽代码；间距 4/8/12/16/24/40/64/96；圆角 ≤16；阴影几乎不可见；动效 ease-out 150ms / 布局移动 quint 曲线。签名：发丝分隔线、快捷键芯片、底部产品截图。避免：emoji、弹性弹簧、第二种饱和色。
- **apple-hig**：大量负空间、一屏一念头、产品在白色上居中；无衬线大标题；克制配色一主一次；动效流体（详见动效 skill）。
- **muji-kenya-hara**：白作为价值、留白即满、商品是主角；低饱和中性色；细字距大标题；信息量最小化。
- **aesop**：奶油/鼠尾草底色、衬线正文如对话、产品图安静居中；字号层级大对比。
- **dieter-rams-braun**：少而优、诚实材质、功能性装饰是矛盾；网格严格、色板克制。
- **vignelli-swiss-helvetica**：瑞士栅格、Helvetica 式无衬线、一生 6 款字体足够；字号层级做全部视觉。
- **bloomberg-terminal**：近黑底 + 琥珀色、等宽数据、任务关键密度；适合数据产品。
- **tufte-dataink**：最大数据墨比、small multiples、最小有效差异；适合数据叙事。
- **monocle**：杂志级 kicker/headline/dek 三层级、国际感克制；适合内容刊物。
- **stripe-press**：编辑感排版 + 高饱和小面积强调、几何图形；适合开发者品牌。

选好配方后把它的 palette/typography/spacing/radius/shadow/motion 值直接填进 Step 3 的设计系统声明块。

## 内容与尺度原则

- 无填充内容：每个元素都要挣得自己的位置；页面显空是构图问题不是内容问题——用构成、留白和字号节奏解决，不要塞内容。
- 不擅自加板块/页面：觉得内容不够先问用户，他们更懂自己的受众。
- 占位 > 伪造；"一千个不换一个要"；留白本身就是设计。
- 尺度底线：Web 正文 16–18px 起；移动端触控目标 ≥ 44px；1920×1080 演示文本 ≥ 24px。
- 标题与正文字号对比 4–6 倍是常态；用比例、留白、色块、纹理、混合模式制造节奏与深度。
- 目标是惊艳：CSS/HTML/JS/SVG 的能力远超多数人认知——按钮按压、卡片悬停、入场动画、`backdrop-filter`、`mix-blend-mode`、`mask`，用它们制造记忆点（但动效决策仍按动效 skill 走）。
